# Plan: PDN-0004 S7 — Layer B evidence, docs, release of v0.5.0

## Context

S1–S6 are merged into `release/v0.5.0`. S7 is the release slice
(`docs/design/PDN-0004-v05-acceptance-recovery.md` §26.2) with the gate that
#22 narrowed (§20.2):

- Layer A green in CI;
- **Layer B** passes on a real host for F1, F2, F11, F14 (changed-task and
  changed-artifact cases), F18 and F27, with zero false acceptance and zero
  silent overlapping writers;
- the release notes state the owner-attestation cost;
- migration table §21 reflected in README;
- `release.yml` green.

Layer B asks one question that Layer A cannot answer: does a real host
follow the skill prose? The host is `claude -p` with the v0.5 skills. The
worker is the test-only fake executor (`tests/harness/fake-executor`),
driven through an executor card so that dispatch treats it like any other
executor. The owner attests stops by hand, and no script records
`owner-attested`.

**Measured before planning (2026-09-25).** A `claude -p` host on the
owner's machine loads **both** passdown channels: plugin `passdown@passdown`
0.4.0 (`passdown:passdown-*`) and the direct v0.5 copies in
`~/.claude/skills` (`passdown-*`). Asked to list them, it even left out the
unnamespaced v0.5 `passdown-dispatch`. Layer B results mean nothing until
the host loads exactly one version (task 1.1).
